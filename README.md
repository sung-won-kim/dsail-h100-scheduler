# DSAIL H100 Scheduler

랩 H100 8장을 시간 단위로 예약하는 웹앱입니다. GitHub Pages(정적 호스팅) + Supabase(데이터 저장) 조합으로 동작합니다.
서버의 gpu-share 도구와 연동되어, 예약된 GPU를 예약 없이 쓰는 작업은 예약 시각에 자동으로 정리되고 서버의 실시간 GPU 현황이 예약 현황 탭에 표시됩니다.

- 시즌: 2026-10-01 → 2027-03-31
- 크레딧 없음. 1인 동시 예약 최대 4장 (`index.html`의 `MAX_CONCURRENT`)
- 파일: `index.html`(앱 전체), `schema.sql`(DB 스키마), `README.md`

`index.html`은 라이브러리 없이 동작하는 단일 파일입니다. 외부에서 불러오는 것은 폰트와 supabase-js(CDN) 두 개뿐입니다.

---

## 설정

코드는 건드릴 필요 없습니다. 파일을 올리고, 앱 화면에서 값 두 개만 넣으면 됩니다.

### 1. 파일 올리기

저장소를 만들어 `index.html`, `schema.sql`, `README.md`, `seed_backup.sql`, `.nojekyll` 을 푸시합니다.

```bash
git init
git add .
git commit -m "DSAIL H100 scheduler"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

**Settings → Pages → Source: Deploy from a branch → main / (root)** 로 지정하면 1~2분 뒤
`https://<계정>.github.io/<저장소>/` 에서 열립니다.

### 2. Supabase 프로젝트 만들기

[supabase.com](https://supabase.com)에서 무료 프로젝트를 하나 만듭니다. 리전은 **Northeast Asia (Seoul)** 이 응답이 빠릅니다.

### 3. 앱 화면에서 연결

배포한 주소를 열면 **서버 연결 설정** 패널이 저절로 떠 있습니다. 여기서 전부 끝납니다.

1. **테이블 만드는 SQL** 버튼 → 클립보드에 복사됩니다. Supabase 대시보드 **SQL Editor**에 붙여넣고 Run.
   (`schema.sql`과 같은 내용이므로 파일을 열어 복사해도 됩니다.)
2. Supabase **Project Settings → API**에서 **Project URL**과 **anon public** 키를 복사해 패널의 두 칸에 넣습니다.
3. **연결 테스트 후 저장**. 잘못된 값이면 무엇이 문제인지(키 오류, 테이블 없음, 정책 없음, 프로젝트 중지 등) 그 자리에서 알려줍니다.

`anon` 키를 쓰세요. **`service_role` 키는 절대 넣지 마세요** — 정책을 무시하는 관리자 키라서 노출되면 DB가 그대로 열립니다. `anon` 키는 브라우저에 노출되도록 설계된 키이므로 링크나 저장소에 들어가도 괜찮습니다.

### 4. 랩원들에게 공유

연결이 끝나면 패널이 두 가지 방법을 보여줍니다.

- **A. 공유 링크** — `...#c=...` 형태의 링크를 복사해 랩 단톡방에 올리면, 각자 아무 설정 없이 바로 연결됩니다. 한 번 열면 그 브라우저에 저장되므로 다음부터는 원래 주소로 들어가도 됩니다.
- **B. 코드에 넣기** (권장) — **CONFIG 코드 복사** 버튼을 눌러 `index.html` 맨 위 `CONFIG` 부분을 그 내용으로 바꿔 커밋하면, 링크 없이 누구나 주소만으로 연결됩니다.

각자 처음 들어가서 오른쪽 위에서 **본인 이름**을 한 번 고르면 그 브라우저에 기억됩니다.

### 5. 확인

- 헤더 배지가 **서버 연결됨**이면 정상입니다. **로컬 데모 모드**면 아직 연결 전이고, 그 상태의 기록은 그 브라우저에만 남습니다.
- 두 사람이 동시에 열고 한쪽에서 예약해 보세요. 상대 화면에 몇 초 안에 나타나야 합니다.
- 문제가 있으면 **규칙 탭 맨 아래 → 저장소 진단**을 누르면 어디서 막혔는지 표시됩니다. 헤더의 **⚙** 버튼으로 설정을 다시 열 수 있습니다.

### (선택) 이전 기록 복원

`seed_backup.sql`에 이전 아티팩트의 예약 2건·송금 6건·요청 3건이 들어 있습니다. 되살리려면 `schema.sql` 실행 후 이 파일을 SQL Editor에서 Run 하세요. 초기화 상태로 시작할 거라면 무시하면 됩니다.

## 알아두면 좋은 것

**접근 권한** — 지금 설정은 주소를 아는 누구나 읽고 쓰고 지울 수 있습니다. 랩 내부 공유라면 충분하지만, 주소가 밖으로 나가면 누구든 예약을 지울 수 있다는 뜻입니다. 나중에 조이고 싶으면 `schema.sql`의 정책 부분만 바꾸면 됩니다(공용 암호, Google 로그인 등).

**동기화** — 다른 사람의 변경은 실시간으로 반영되고, 소켓이 끊기면 15초 폴링이 받쳐줍니다. 헤더의 ↻ 버튼으로 언제든 직접 불러올 수 있고, 옆에 마지막 동기화 시각이 표시됩니다. 서버와 통신이 안 되는 동안에는 빨간 띠가 뜨고 저장이 막히므로, 오래된 화면 위에 덮어써서 남의 기록이 사라지는 일은 없습니다.

**동시 예약** — 같은 GPU·같은 시간대를 두 사람이 동시에 잡으면 잠금과 저장 직전 재확인으로 한쪽이 거절됩니다.

**초기 데이터** — 서버의 `members`가 비어 있을 때만 멤버 26명(각 1,344 크레딧)을 자동으로 넣습니다. 이미 데이터가 있으면 아무것도 건드리지 않습니다. 예약·송금·요청은 빈 상태로 시작합니다.

**멤버 추가/삭제** — `index.html`의 `ROSTER`(이름·학위과정)와 `ROSTER_SEED`(초기 크레딧)를 수정하고, 이미 시딩이 끝난 뒤라면 Supabase **Table Editor**에서 `dsail_rows`에 `coll=members`, `id=<영문-아이디>`, `data={"name":"...","role":"phd","initial":1344}` 행을 직접 추가하세요.

**서버 접속 탭** — H100 서버 SSH 접속 매뉴얼입니다. 접속 주소나 포트가 바뀌면 `index.html` 맨 아래 스크립트의 `HostName`/`Port` 두 값만 고치면 됩니다. 계정 생성은 관리자가 서버에서 따로 합니다.

**프로필 사진** — 기본 사진은 `index.html`에 base64로 들어 있습니다. 각자 앱에서 바꾼 사진은 `dsail_rows`의 members 행에 저장됩니다.

**무료 플랜** — 일정 기간 아무도 접속하지 않으면 프로젝트가 일시 중지될 수 있습니다. 그러면 대시보드에서 Resume 한 번 누르면 됩니다. 학기 중이라면 사실상 겪지 않습니다.

**백업** — 중요한 시점에는 Table Editor에서 `dsail_rows`를 CSV로 내려두면 충분합니다.

## 서버 연동 (gpu-share)

H100 서버에서 1분마다 실행되는 도구가 anon 키로 이 앱의 `bookings`를 읽고, 다음을 합니다.

- 예약된 GPU를 예약자가 아닌 사람이 쓰고 있으면 터미널로 경고하고(시작 10분 전, 방금 잡힌 예약이면 10분 유예) 예약 시각에 그 프로세스를 종료합니다.
- GPU별 사용자·사용률·예약 상태를 `dsail_rows`의 `coll=meta, id=gpu-status` 행에 올립니다. 예약 현황 탭 위쪽 "지금 서버 GPU"가 이 행을 보여줍니다.

서버 계정과 이 앱의 멤버 id는 서버의 `/etc/gpu-share/accounts.txt`로 연결합니다. 도구 코드와 설치 방법은 관리자 계정의 `~/lab-admin/gpu-share/`에 있고, 앱의 서버 접속 탭(관리자 이름 선택 시)에 운영 매뉴얼이 있습니다.

크레딧·송금·요청 기능은 내렸습니다. 관련 코드와 데이터(`transfers`, `requests`, 멤버의 `initial`)는 남아 있지만 화면에는 나오지 않습니다.
